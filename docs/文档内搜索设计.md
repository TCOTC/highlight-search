# 文档内搜索设计

在当前打开的思源文档里做「查找」，不依赖浏览器原生 Find，也不整篇塞进 DOM。

## 当前文档

可搜索的编辑器按黑名单判定：`getAllEditor()` 里排除片段编辑器（`data-protyle-lite="true"` 或 `.protyle-lite-fragment`：文档名富文本、表格单元格、数据库单元格、脑图、AI 输入框）、嵌在其他 Protyle 内的编辑器，以及不可见的编辑器（后台页签落在 `fn__none` 内）。页签正文、块浮窗、反链浮窗与全局搜索预览都自然落入可搜索范围，新增界面不必单独登记。

反链浮窗里每条反链各自一个 Protyle，但整个浮窗作为一个范围、共用一个搜索框，因此能一次搜到所有反链条目。浮窗处于打开状态时优先在浮窗内搜索（钉住的浮窗会与文档并行使用，不抢占），点击反链图标等操作后焦点仍停在文档里时也能搜浮窗。

搜索范围包含文档标题：标题文本单独从标题的可编辑载体 `.protyle-title__input` 读取，命中归到标题元素的 `data-node-id`（文档块 ID），因此普通标题与富文本标题都能搜到，且不会把富文本标题里的临时段落当作独立块计数。富文本标题是一个完整的片段编辑器，其中的预览、工具栏等面板即使隐藏仍在 DOM 里，因此不能按整个 `.protyle-title` 取文本。标题被隐藏（如聚焦缩放）时不计数也不高亮。焦点落在不可搜索的编辑器（如片段编辑器）上时回退到活动页签。浮窗与全局搜索预览只渲染一段上下文，因此这类范围只扫自身 DOM，不按整篇文档取候选。

## 为什么要混合

思源编辑器会按滚动窗口动态加载 / 卸载块。只扫已渲染 DOM 会漏掉未加载内容。

因此拆成两层：

| 层 | 职责 |
|----|------|
| **Match 列表** | 全文档有哪些命中（含未加载块） |
| **DOM 高亮** | 只给当前视口里看得见的文本上色 |

```text
输入关键词
    │
    ▼
SQL 粗筛候选块
    │
    ▼
可见文本：已在编辑器且可见 → 活 DOM；其余 → getBlockDOMs 离屏
（与「文档序」请求并行）
    │
    ▼
按文档阅读序排好（见下「文档序」）
    │
    ▼
展开为 Match 列表（blockId + 块内第几次）
    │
    ├─► 计数 / 结果面板
    └─► 当前 DOM 上 CSS Highlight；跳转时按需装载块
```

## 文档序

Match 列表必须按编辑区从上到下的**原文顺序**（文档树深度优先，嵌套块各自有先后），不能用 `getBlocksIndexes`：后者语义是顶层子块序号，列表项内多个段落会落到同一顶层 index，无法区分先后。

排序走 [`/api/block/getDocBlocksOrders`](https://github.com/siyuan-note/siyuan/issues/18416)：传入文档 `id`，返回该文档内全部块的深度优先原文序。该请求与可见文本解析并行；拿到命中子集后按文档序单次扫描排列（不必再 sort）。

若接口失败返回空序，命中块保持 SQL 粗筛顺序（未必等于阅读序）。

## 一条命中是什么

```ts
{ blockId, occ }  // 某块内第 occ 次出现（从 0 起）
```

这是跨卸载仍稳定的主键。`Range` / 当前下标只是视口投影，动态加载后会重扫高亮，但 **不会重置** 当前 Match 下标。

## 可见文本

思源索引的 `blocks.content` 会把超链接的 URL 也拼进去，搜 `Flowchart` 时可能同时命中锚文本和 `https://flowchart.js.org/`。

计数与 snippet **不以 content 为准**，而是按块取可见正文：

1. **已在当前编辑器且可见**（`clientHeight > 0` 且非折叠祖先下）：直接用活 DOM，与高亮共用 [`collectOwnTextNodes`](../src/visible-text/collect.ts)，保证 occ 偏移一致，并跳过该块的 `getBlockDOMs`
2. **未加载 / 折叠隐藏等**：`/api/block/getBlockDOMs` 离屏挂载 → 官方 Protyle 渲染 → 抽**元素内实际可见文本**（与高亮同一套规则）  
   - mermaid / flowchart 等：离屏会撑开宽度并等待 SVG；若仍抽不到正文，才回退 `data-content`（避免整块漏检）  
   - 已在编辑器且 SVG 已画出时，Match 列表与高亮都只认 DOM 正文，不用源码冒充列表文案
3. 在可见文本上按 [`match-text.ts`](../src/match-text.ts) 数出现次数

跳过 `.protyle-attr` / `style` / `script` / 未渲染公式 / 嵌套子块等；`data-href` 等属性不会进入文本。

正文根只取搜索范围自己的 `.protyle-wysiwyg` / 预览，反链浮窗这类容器则取其内每个条目的正文根。文档标题另行从 `.protyle-title__input` 读取文本，富文本标题里的临时段落不作为独立块计数；表格单元格富文本等片段编辑器的临时块不进入搜索。列表、引述、超级块、原生标签页、脑图等容器只承载子块，不把自身生成的导航 / 预览控件算作正文；Callout 标题属于用户正文，仍按容器自身可见文本扫描。

定位时若 `occ` 与 DOM 不一致，优先用 snippet 命中文本对齐 Range，避免「最近 occ」指错元素。

## 跳转到未加载 / 不可见块

不用自己拼 `getDoc`，也不手动改折叠 DOM。下列情况一律走公开 API，交给思源（对齐 `siyuan://blocks/` 的 `checkFold`）：

- 块不在当前 DOM
- 块在折叠列表 / 折叠标题下（祖先 `fold="1"`，滚动也看不见）
- 块 `clientHeight === 0`

原生标签页里未选中的页签内容仍在 DOM，但被 `data-tabs-hidden="true"` 隐藏。这类块同样先点击对应页签标题（含嵌套标签页）让其显示，再按普通 DOM 命中滚动；无法点击时仍走下面的思源跳转。

先调 `/api/block/checkBlockFold`：

| 情况 | action | 其它 |
|------|--------|------|
| 在折叠内 | `cb-get-focus` + `cb-get-all` | `zoomIn: true` |
| 否则 | `cb-get-focus` + `cb-get-context` + `cb-get-rootscroll` | |

- 桌面：`openTab({ doc: { id, action, zoomIn? } })`
- 移动：`openMobileFileById(..., action)`

`cb-get-focus` 才会在 `onGet` 里 `focusBlock` + `scrollCenter`；仅有 `cb-get-context` 不会聚焦。  
**不做** `cb-get-hl`（官方块闪烁）。词级高亮仍由插件的 `CSS.highlights`（`search-results` / `search-focus`）完成。

块已在 DOM 且未被折叠隐藏时，直接滚到对应 Range，避免多余跳转。

## 匹配规则

Match 列表与 DOM 高亮共用 [`match-text.ts`](../src/match-text.ts)：

- 规范化关键词（纯空白可搜）
- 大小写：每个搜索框独立开关，新建时默认取思源「设置 → 搜索」的区分大小写
- 空白与零宽字符变体（与历史行为一致）

## 刻意不做

- Electron `findInPage`（对 Protyle 虚拟化无效）
- 默认整篇 `cb-get-all` 进 DOM
- 依赖未导出的官方 `searchMarkRender`
