# 文档内搜索设计

在当前打开的思源文档里做「查找」，不依赖浏览器原生 Find，也不整篇塞进 DOM。

## 为什么要混合

思源编辑器会按滚动窗口动态加载 / 卸载块。只扫已渲染 DOM 会漏掉未加载内容。

因此拆成两层：

| 层 | 职责 |
|----|------|
| **Match 列表** | 全文档有哪些命中（含未加载块） |
| **DOM 高亮** | 只给当前视口里看得见的文本上色 |

```text
输入关键词
    │
    ▼
SQL / FTS 粗筛候选块
    │
    ▼
getBlockDOMs → 解析可见文本（不含链接 URL 等属性）
    │
    ▼
getBlocksIndexes → 按文档阅读序排好
    │
    ▼
展开为 Match 列表（blockId + 块内第几次）
    │
    ├─► 计数 / 结果面板
    └─► 当前 DOM 上 CSS Highlight；跳转时按需装载块
```

## 一条命中是什么

```ts
{ blockId, occ }  // 某块内第 occ 次出现（从 0 起）
```

这是跨卸载仍稳定的主键。`Range` / 当前下标只是视口投影，动态加载后会重扫高亮，但 **不会重置** 当前 Match 下标。

## 可见文本

思源索引的 `blocks.content` 会把超链接的 URL 也拼进去，搜 `Flowchart` 时可能同时命中锚文本和 `https://flowchart.js.org/`。

计数与 snippet **不以 content 为准**，而是：

1. `/api/block/getBlockDOMs` 取块 HTML  
2. 取可见 `textContent`（去掉 `.protyle-attr` / `style` / `script`）  
3. 在可见文本上按同一套规则数出现次数  

编辑器内高亮扫描同样只认可见正文。

## 跳转到未加载块

不用自己拼 `getDoc`。块不在 DOM 时走公开 API：

- 桌面：`openTab({ doc: { id, action: ["cb-get-context"] } })`
- 移动：`openMobileFileById(..., ["cb-get-context"])`

只负责把块装进视口；**不做**官方块闪烁。词级高亮仍由插件的 `CSS.highlights`（`search-results` / `search-focus`）完成。

块已在 DOM 时直接滚到对应 Range，避免多余跳转。

## 匹配规则

Match 列表与 DOM 高亮共用 [`match-text.ts`](../src/match-text.ts)：

- 规范化关键词（纯空白可搜）
- 大小写：跟随思源 / 强制开 / 强制关
- 空白与零宽字符变体（与历史行为一致）

## 相关文件

| 文件 | 作用 |
|------|------|
| `src/block-search.ts` | 粗筛（SQL 显式大 LIMIT）→ DOM 可见文本（批并发）→ 文档序 → Match 列表（每块只匹配一次） |
| `src/find-session.ts` | 会话：列表、当前下标、定位 |
| `src/locate.ts` | `openTab` / 已在 DOM 时的定位 |
| `src/visible-text.ts` | 从块 HTML 提取可见文本 |
| `src/search.ts` | 按块扫 DOM + CSS Highlight |
| `src/search-box.ts` | UI、防抖、结果面板（虚拟列表）、事件刷新 |

## 刻意不做

- Electron `findInPage`（对 Protyle 虚拟化无效）
- 默认整篇 `cb-get-all` 进 DOM
- 依赖未导出的官方 `searchMarkRender`
